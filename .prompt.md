# .prompt.md — Prompt governance vincoli e regole RD2229

## Scopo
Garantire che ogni vincolo architetturale (“vincolo duro”), regola operativa, convenzione di memoria, mapping dipendenze e lesson learned sia sempre:
- Esplicitato e aggiornato nella sezione "Vincoli architetturali" di PIANO_LAVORO.md (fonte di verità)
- Dettagliato nei file markdown tematici in docs/memory/ se necessario
- Tracciato con hash commit, stato, note e riferimenti
- Accessibile e rispettato da tutti gli agenti, LLM e collaboratori

## Istruzioni operative
Quando viene introdotto, modificato o raffinato un vincolo/regola/convenzione:
1. Leggi sempre PIANO_LAVORO.md e i file in docs/memory/ prima di qualsiasi operazione.
2. Aggiorna la sezione "Vincoli architetturali" in PIANO_LAVORO.md con:
   - Descrizione chiara del vincolo/regola/convenzione
   - Stato (attivo, modificato, deprecato, ecc.)
   - Hash commit, note, riferimenti a subplan o memory
3. Se necessario, aggiorna/crea il file tematico in docs/memory/ con i dettagli (seguendo la forma di MEMORY.md e dei subplan).
4. Non lasciare mai decisioni architetturali, lesson learned o regole solo in commenti, issue, PR o chat.
5. Dopo ogni avanzamento, completamento di sub-fase o modifica, aggiorna PIANO_LAVORO.md e i file di memory.
6. Ogni nuovo agente o collaboratore deve essere istruito a rispettare queste regole.

## Input impliciti
- File PIANO_LAVORO.md (fonte di verità)
- File markdown tematici in docs/memory/ (MEMORY.md, subplan, ecc.)
- Stato attuale del repository e delle convenzioni

## Output desiderato
- Sezione aggiornata "Vincoli architetturali" in PIANO_LAVORO.md (seguendo la struttura esistente)
- (Opzionale) Aggiornamento/creazione file in docs/memory/ (seguendo la forma di MEMORY.md e subplan)
- Tracciabilità completa (hash commit, note, riferimenti)
- Nessuna informazione lasciata solo in chat, commenti o issue

## Esempi di invocazione
- “Aggiungi nuovo vincolo architetturale su modularità”
- “Aggiorna regola operativa su help contestuale”
- “Registra lesson learned su retrocompatibilità”
- “Mappa nuova dipendenza tra moduli in PIANO_LAVORO.md e memory”

---

> Struttura e stile devono essere coerenti con la sezione "Vincoli architetturali" di PIANO_LAVORO.md e con i file MEMORY.md/subplan in docs/memory/.
> Prompt valido solo per il workspace RD2229.
